# Terax Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Enviar archivos entre Android y Windows con swipe, animación y apertura opcional de imágenes.

**Architecture:** Proyecto Flutter compartido. Transporte HTTPS fijado por huella, autorización por token QR de sesión, streaming y hash antes de publicar archivos recibidos. UI usa controlador separado del transporte.

**Tech Stack:** Flutter/Dart, basic_utils, crypto, file_picker, qr_flutter, mobile_scanner, open_filex.

**Spec:** docs/superpowers/specs/2026-10-27-terax-design.md

## Global Constraints
- Android y Windows en la misma LAN; sin nube.
- Máximo 1 GiB por archivo y una recepción simultánea.
- Apertura automática solo de imágenes decodificables y con opción explícita.
- La animación no representa éxito hasta confirmar bytes y SHA-256.

## Review Focus
- Credenciales o certificado incorrectos: rechazar sin crear archivos finales.
- Nombres maliciosos o repetidos: no escapar del directorio ni sobrescribir.
- Desconexión, hash o tamaño incorrectos: limpiar temporales y liberar receptor.
- Doble gesto o recepción concurrente: evitar duplicados y responder ocupado.
- Pantalla móvil estrecha o movimiento reducido: controles accesibles y animación opcional.

## Decisiones durante ejecución
- El usuario aclaró que esperaba cercanía y autorización inicial única. Se reemplazó el token de sesión por identidad protegida persistente; no se conserva el flujo de escaneo repetido.
- Descubrimiento por UDP firmado en lugar de mDNS: permite aprender la nueva dirección solo a equipos ya autorizados, sin publicar secretos.
- Windows usa un publicador BLE nativo nuevo por arranque, evitando acumulación de UUIDs del plugin. El plugin se utiliza para escaneo Android.
- La compilación con MSVC 2026 requiere retirar /await del target del plugin y usar C++20 estándar; el ajuste está en CMake del proyecto, sin editar cachés de dependencias.
